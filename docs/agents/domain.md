# 领域文档

工程类技能在探索代码前，按这里的规则读取本仓库的领域文档。

## 探索前先读

- **`GLOSSARY.md`**（仓库根目录）：本仓库是单上下文，只有这一份。
- **`docs/adr/`**：读与当前改动区域相关的 ADR。

文件不存在就静默跳过，不要提示补齐：`domain-modeling` 会在术语或决定真正定下来时按需创建。

## 目录结构

单上下文（本仓库采用的布局）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-keep-wire-field-names.md
│   └── ...
└── src/
```

## 使用 GLOSSARY.md 的词汇

输出里提到领域概念时（issue 标题、重构提议、假设、测试名），用 `GLOSSARY.md` 定义的那个词，不要漂移到它标记为 `_Avoid_` 的同义词。

概念不在词表里是个信号：要么你在发明项目不用的语言（重新想想），要么确实有缺口（记下来交给 `domain-modeling`）。

## 冲突要显式说明

如果结论与某条 ADR 冲突，明确说出来，而不是悄悄覆盖：

> _与 ADR-0002（工具失败折成 ERROR 文本）冲突，但值得重开，因为……_
