# 权限设计方案（Permission Design）

- 项目：wwxst/agent-Kernel
- 设计版本：Permission v0.2
- 状态：产品设计已确定；**当前代码只实现 Full Access**
- 本文用途：记录权限设计决策，作为后续代码重构与验收依据

> **实现状态（2026-11-12）**：第 2 节的「人工审批 / AI 审批」是未来产品设计，**代码中不存在**；
> 当前实现只有完全访问。具体实现对照见第 14 节。

## 1. 设计目标与核心原则

agent-Kernel 是面向开发者的本地 Coding Agent。权限系统的目标是让开发者能够把任务交给 Agent，由 Agent 自主完成工作，而不是被频繁的权限弹窗打断。

核心原则：

> Set boundaries first, then grant freedom.
>
> 先划定边界，再给予自由。

设计时必须区分三个不同层面：

1. **Agent 自身的权限策略**：agent-Kernel 是否主动限制文件、命令和网络操作。
2. **操作系统安全边界**：当前操作系统账户实际拥有的文件、进程和网络权限。
3. **程序稳定性保护**：参数校验、超时、取消、输出上限、进程清理和错误处理等机制。

取消 Agent 自身施加的工作区限制，不等于绕过操作系统权限，也不等于自动获得管理员权限。

## 2. 产品层面的三种权限模式

产品设计保留三个清晰的权限概念。它们描述的是 Agent 在遇到权限边界时，采用什么授权方式。

### 2.1 人工审批（Manual Approval）

定位：由用户掌握额外授权的最终决定权。

- Agent 在受限工作区内自主完成正常工作。
- 工作区内符合策略的文件操作和命令不需要逐次询问。
- 操作超出当前沙盒或策略边界时，向用户请求批准。
- 用户可以批准或拒绝该次请求。
- 授权应与具体操作和目标资源绑定，不能因为批准一次就无边界地扩大权限。

### 2.2 AI 审批（AI Approval）

定位：在与人工审批相同的基础安全边界内，使用独立审核 AI 减少人工打断。

- 基础沙盒范围与人工审批模式相同。
- 正常范围内的操作自主执行。
- 需要额外审批的操作交给独立审核器判断。
- 审核器需要结合用户任务、待执行操作、目标资源和潜在影响进行判断。
- 正在执行任务的 Agent 不能自行给自己的请求审批。
- 审核器只能在明确授权边界内批准，不得自行扩大沙盒权限。
- 审核器拒绝、超时、异常或无法判断时，不得默认放行。
- 对需要用户明确意图或可能造成重大后果的操作，可以要求人工确认。

AI 审批是风险判断辅助，不是操作系统沙盒，也不是安全保证。

### 2.3 完全访问（Full Access）

定位：面向明确信任 Agent 的开发者和自动化任务，取消 agent-Kernel 自身的工作区访问边界与普通权限审批。

- Agent 可以使用当前操作系统账户有权访问的文件和目录。
- 可以读取、创建、修改和删除文件。
- 可以在当前工作区之外执行命令。
- 可以正常访问互联网。
- 不需要普通权限审批。
- 不由 agent-Kernel 强制限制在某一个工作区目录内。

完全访问仍然受当前操作系统账户权限、操作系统安全机制、进程运行环境和网络配置约束。它不会自动获取 root、sudo 或 Windows 管理员权限，也不会绕过系统防火墙、代理或其他系统级限制。

## 3. 本期范围：只实现 Full Access

**本期只实现 Full Access。人工审批和 AI 审批只保留为未来产品设计，不进入当前代码实现。**

本期明确要求：

- 只保留一个运行模式：**full-access**。
- **full-access** 是所有启动入口的默认且唯一模式。
- 清理旧的 **read-only** 和 **workspace-write** 模式。
- 清理旧模式对应的判断分支、模式切换、审批 UI 和无用代码。
- 不实现人工审批。
- 不实现 AI 审批或独立审核 Agent。
- 不实现审批授权缓存、授权记忆或复杂策略规则引擎。
- 不为了未来多模式预先搭建复杂抽象。
- 不保留旧模式的兼容分支。

未来如需实现人工审批或 AI 审批，应基于届时真实的安全需求重新设计。不能因为本文记录了未来方向，就在本期提前实现相关代码。

## 4. Full Access 的能力定义

| 能力 | 本期行为 |
| --- | --- |
| 读取当前账户有权访问的文件 | 允许 |
| 在有权访问的目录创建文件 | 允许 |
| 修改文件 | 允许 |
| 删除文件和目录 | 允许 |
| 访问当前工作区之外的路径 | 允许 |
| 访问其他项目目录 | 允许 |
| 执行 Shell 命令 | 允许 |
| 在工作区之外执行命令 | 允许 |
| 使用当前环境可用的开发工具 | 允许 |
| 访问互联网 | 不施加 Agent 层面的额外限制 |
| 普通权限审批 | 不需要 |
| Agent 自身的工作区路径限制 | 不施加 |

这里的“允许”表示 agent-Kernel 不额外拒绝该操作；实际能否成功，仍由操作系统账户权限和运行环境决定。

Full Access 只开放当前已注册工具所能提供的能力，不会凭空增加图形界面控制、浏览器控制或其他尚未注册的工具。

## 5. 文件工具设计

当前内置文件工具包括：

- **read**：读取文件。
- **write**：创建或覆盖文件。
- **edit**：按匹配内容修改文件。
- **ls**：列出目录内容。
- **glob**：按模式查找文件。
- **grep**：搜索文件内容。

这些工具不应再把当前工作区根目录当作权限边界。

### 5.1 路径解析规则

- 相对路径继续相对于当前工作区根目录解析，保持现有调用习惯。
- 绝对路径直接指向用户指定的位置。
- 允许通过 **..** 访问工作区上级目录。
- 允许访问其他项目目录和临时目录。
- 符号链接及 Windows junction 遵循操作系统实际路径语义；目标位置只要是当前账户有权访问的资源，就不应仅因目标位于工作区之外而被拒绝。
- 支持 POSIX 路径、Windows 盘符路径及适用的 UNC 路径。
- 文件不存在、路径无效或操作系统拒绝访问时，返回清晰错误，不伪装成权限策略拒绝。

路径规范化仍然是正确定位资源所必需的，但不能再用它实施“必须位于工作区内”的限制。

### 5.2 搜索范围与资源预算

Full Access 不代表每次搜索都默认扫描整台电脑。

- **glob** 和 **grep** 应在调用者指定的路径范围内搜索；未指定时沿用当前工作区作为默认搜索根目录。
- 保留现有通配符语义、忽略规则、扫描预算、命中数量限制和结果截断说明。
- 搜索提前停止时，明确说明结果可能不完整。
- 保留对 **.git**、**node_modules** 等目录的既有默认忽略行为，除非用户明确指定搜索它们。
- 不因取消工作区边界而无意扩大默认扫描量。

### 5.3 文件操作可靠性

继续保留已有的原子写入、编辑匹配校验、取消检查、读取大小限制和错误处理。

Full Access 取消的是 Agent 层面的路径拒绝，不是文件操作可靠性要求。

## 6. Shell 执行设计

Shell 继续以启动 agent-Kernel 的当前操作系统账户执行。

- 不需要逐次人工审批。
- 不限制命令必须在工作区内执行。
- 默认工作目录继续使用当前工作区，除非调用明确指定其他工作目录或命令自行切换目录。
- 允许使用绝对路径、切换目录以及访问工作区外的资源。
- 不对普通 Shell 命令施加 Agent 层面的命令白名单或工作区路径限制。
- 不自动使用 sudo、管理员权限提升或其他提权方式。

必须保留现有运行稳定性机制：

- 命令超时。
- 标准输出和标准错误处理。
- 输出长度限制。
- AbortSignal 与 Ctrl+C 取消。
- 子进程退出状态处理。
- 子进程或进程树清理。
- 工作目录处理和跨平台兼容。
- 清理未能确认时如实报告，不能假称进程已经全部退出。

## 7. 网络访问设计

Full Access 不由 agent-Kernel 额外限制 Agent 的网络访问。

- 不增加 Agent 层面的网络开关。
- 不增加域名白名单或黑名单。
- 不增加网络审批。
- Shell 子进程和当前已注册的网络工具使用运行环境本身可用的网络能力。
- 支持正常的软件包安装、依赖下载、Git 远程操作和 API 访问。

不绕过操作系统防火墙、代理、证书配置或网络管理员设置。网络连接失败时，按真实网络错误返回。

模型服务本身与 Agent 工具的网络访问是两个不同层面：本设计取消的是 Agent 工具侧额外施加的限制，不改变模型客户端已有的连接配置。

## 8. 执行入口与代码结构

当前 Agent 的核心循环应尽量保持不变：Agent 负责组织模型请求和工具调用，ToolRegistry 负责统一工具入口，Workspace 负责文件与 Shell 的实际操作。

建议职责：

| 模块 | 职责 |
| --- | --- |
| **Agent** | 负责模型交互、工具调用循环和取消生命周期；不负责权限审批 |
| **ToolRegistry** | 负责工具注册、参数 Schema 校验、调用分发和错误结果整理 |
| **Workspace** | 负责文件工具、路径解析、搜索和 Shell 执行 |
| **CLI / REPL / TUI** | 负责启动、交互和状态展示；不提供权限模式切换 |

实现时应检查 Permission 是否仍有实际职责：

- 如果它只剩下旧模式判断和审批逻辑，应删除，不要为了保留文件而留下空壳。
- 如果运行时确实需要标识当前模式，只保留单一的 **full-access** 常量或字面量类型。
- 不保留多模式枚举、策略分发器或没有实际用途的权限注入参数。
- **ToolRegistry** 不应继续要求调用方传入一个实际上不执行任何判断的 Permission 对象。

所有启动入口统一使用 Full Access，不允许 CLI、REPL、TUI、测试装配或程序化入口出现不同默认值。

## 9. CLI、REPL、TUI 与模型提示

### CLI

- 默认且唯一使用 Full Access。
- 删除 **--permission** 参数及相关帮助信息。
- 不再要求用户选择权限模式。

### REPL

- 本版本已移除逐行 REPL（`--repl` 会报错），TUI 是唯一交互界面；因此也不存在 `/permission`。
- TUI 中保留 **/help**、**/reset**、**/exit** 等与权限无关的正常功能。
- 不再提供权限切换。

### TUI

- 删除权限切换快捷键、审批菜单、审批等待状态和权限升级确认。
- 不再显示旧模式名称。
- 如需显示当前模式，只显示固定状态“完全访问（Full Access）”，不提供切换入口。

### 模型提示

System Prompt 和工具描述应与真实能力一致：

- Agent 当前运行于 Full Access。
- 文件工具可以访问工作区之外、当前账户有权访问的路径。
- Shell 不需要普通审批，也不受 Agent 工作区路径限制。
- Agent 工具侧没有额外的网络白名单限制。

Prompt 只负责告诉模型当前能力，不是安全边界。真实行为由工具实现和操作系统决定。不能出现代码已经允许访问，但 Prompt 仍告诉模型“只能操作当前工作区”的矛盾。

## 10. 必须保留的稳定性与系统边界

Full Access 不等于删除所有保护。以下机制继续保留：

- 工具参数校验。
- 路径解析和跨平台兼容。
- 文件读取大小限制。
- 搜索目录项、匹配数量和执行时间预算。
- 正则搜索 worker 的超时终止。
- 文件原子写入与失败清理。
- 编辑内容唯一匹配校验。
- 写入前的取消检查。
- Shell 超时与输出上限。
- 取消信号传播。
- 子进程清理和退出状态检查。
- 错误规范化与非空错误结果。
- Agent 的模型请求预算、工具调用预算和运行取消机制。

这些属于稳定性、资源控制或系统边界，不属于人工审批。

Full Access 是高信任模式。它可能读取密钥、修改其他项目、删除用户文件或执行有副作用的程序。用户应只对自己信任的 Agent、任务和项目使用它。项目代码、依赖脚本和模型生成的命令都可能产生意外副作用。

如果 Agent 运行在容器、受管理的开发环境或其他外部沙盒中，外部环境的限制仍然生效；agent-Kernel 不尝试绕过它们。

## 11. 验收标准

本期实现完成后，应至少验证：

### 文件访问

- 可以读取工作区外文件。
- 可以在工作区外创建、修改和删除文件。
- 可以访问绝对路径和 **..** 相对路径。
- 可以列出工作区外目录。
- 可以在明确指定的工作区外目录运行 **glob** 和 **grep**。
- 符号链接或 junction 指向工作区外时，按当前账户权限正常访问。
- POSIX 与 Windows 路径行为符合各自平台语义。
- 权限不足、路径不存在等情况返回准确错误。

### Shell 与网络

- Shell 不再请求普通审批。
- 可以在工作区外执行命令。
- Shell 超时、取消、输出限制和进程清理仍然有效。
- 不存在 Agent 层面的额外网络白名单或审批。
- 网络行为遵循当前运行环境配置。

### 旧模式清理

- 当前代码只保留 **full-access**。
- 不再有 **read-only** 和 **workspace-write** 的运行时分支。
- 不再有 **/permission**、**--permission** 和 Shift+Tab 权限切换。
- 不再有 Shell 人工审批和 AI 审批实现。
- 不再有无用的审批 UI、等待状态和审批回调。
- README、CLI 帮助、TUI 文案和当前架构说明不再宣称存在旧模式。

### 回归验证

- 原有 Agent Loop 正常。
- 九个内置工具正常（`read` / `write` / `edit` / `glob` / `grep` / `ls` / `shell` / `shell-output` / `shell-kill`）。
- CLI、REPL、TUI 正常。
- Ctrl+C 和 AbortSignal 正常。
- 原有超时、输出预算、文件写入可靠性和错误处理测试通过。
- TypeScript 类型检查和项目测试通过。

测试只能操作临时目录和测试进程，不得触碰开发者真实文件。

## 14. 当前实现对照（2026-11-12）

| 设计要求 | 代码位置 / 事实 |
| --- | --- |
| 唯一模式 Full Access | `ToolRegistry` 不再接受 `permission` 参数；源码中没有 `Permission` 类型、`read-only`、`workspace-write` |
| 没有人工 / AI 审批 | 没有审批提示、审批菜单、审批回调或审核器；`src/approval.ts` 已删除 |
| 文件工具无工作区边界 | `Workspace.resolve()` = `path.resolve(root, requested)`；`Workspace.resolveReal()` 只解析真实路径，不判边界 |
| 绝对路径 / `../` / 其他磁盘 | `resolve` 直接使用绝对路径；`../` 不做拒绝；Windows 盘符与 UNC 由 `path` 处理 |
| 符号链接 / junction | `resolveReal` 用 `realpath` 解析到实际目标；目标不存在时沿父目录拼回 |
| glob 指定搜索根 | `Workspace.glob(pattern, path)`；默认 `path="."`；绝对模式由 `splitAbsoluteGlob` 拆分 |
| grep 工作区外搜索 | `Workspace.grep(pattern, path)`；默认目录外结果用绝对路径 |
| Shell 无审批、可出工作区 | `Workspace.run()` 直接 `spawn`；默认 cwd 为 `WORKDIR`，命令内可 `cd` |
| 没有网络白名单 | `src/llm.ts` 只有发往 `BASE_URL` 的 `fetch`；没有域名过滤或网络开关 |
| 稳定性保护保留 | 超时、8k 输出上限、`AbortSignal`、进程树清理、原子写入、有界读取、扫描预算、正则 worker 超时 |
| CLI 移除 `--permission` | `parseArgs` 对 `--permission` / `AGENT_PERMISSION` 直接报错 |
| TUI 固定状态 | 状态栏 `权限：完全访问` / `access: full-access`；没有审批 UI、`Shift+Tab`、`/permission` |
| 模型提示一致 | `DEFAULT_SYSTEM_PROMPT` 说明 full access、无目录边界、无需请求授权 |
