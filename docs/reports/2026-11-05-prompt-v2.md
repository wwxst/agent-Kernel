## 1. 改了什么

默认系统提示词多了一行：

> Run one shell command per call with simple syntax; do not use | to sequence commands or alternate quoting.

（每次只跑一条 shell 命令、用简单语法；不要用竖线串联命令，也不要换着引号写。）

**为什么**：诊断报告里 13、20、08 三个高方差任务的绕路根因不是任务难度，而是模型把 POSIX 风格写法用在 Windows shell 上——`|` 当分隔符、`rm` 不存在、`/tmp` 越界。每次失败都要多一轮模型请求，而每一轮都要重发完整历史。候选 B 在 3 个任务上 5 轮 15/15、请求 -20%、tokens -26%；完整 20 任务跑过一轮 20/20、119,749 tokens。

**测试**：`test/agent.test.mjs` 增加一条断言，锁住这行提示词，避免以后重构时被静默丢掉。

观察：

1. **收益不只是均值，主要是尾部。** v1 最贵的一轮 167,609，v2 最贵 125,650；轮间倍数从 1.42× 降到 1.22×。成本预算的不确定性明显变小。
2. **v1 里的 5 倍离群基本消失。** 13 和 20 都还有 2–3.8× 的波动，但极端轮次（13 的 4 请求对 14 请求、20 的 4 对 14）没有再出现。这与「少一次语法失败 = 少一整轮」的解释一致。
3. **完整集上的收益（-12% 请求 / -14.5% tokens）小于 3 个任务上的 A/B（-20% / -26%）**，符合预期：13/20/08 正是受影响最大的任务，全量里还有大量本来就不调用 shell 的任务。
4. **06 的离群没有出现**：v2 六轮最大 5 请求，而 v1 的 Day 1 出现过 19 请求。但这不能归功于提示词——那一次本来就没复现，样本也不足以下因果结论。

## 4. 口径与限制

- 单模型、单机、同一天 6 轮；**跨天验证在 v2 上还没开始**。
- 提示词是全局的，影响所有 shell 用法，不只是失败场景。理论上会限制「必须用管道才自然」的写法；20 个任务里没有出现因此失败的情况，但任务集本身不覆盖复杂 shell 管道。
- 六轮里 13 仍有 6,358–23,886 的波动，说明模型绕路没有消失，只是变少了。成本预测仍应按中位数加余量。
- 本轮没有改 Agent Loop、工具实现、预算语义或任何评测任务；唯一的行为改动就是这一行提示词。
