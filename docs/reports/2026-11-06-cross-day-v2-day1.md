## 4. 运行期间的一次环境干扰（数据仍可用）

运行开始时工作树在 `main`（`da8f179`），运行器按协议 `git checkout --detach eac798d` 后开始第 1 轮。**08:49:08 另一个会话把工作树切到了 `feat/permission-v0.1` 并在其中改文件**（`src/tui.ts`、`src/cli.ts`、`test/tui.test.mjs`），运行器结束时的 `git checkout main` 因此失败，进程以非 0 退出；三轮结果和一个完整的 `summary.json` 仍然写进了归档。

对数据的影响：

- 运行器在 08:47:40 checkout 完成后立即 import 了 `eac798d` 的 `eval/run.mjs` 与 `src/*.ts`，Node 会缓存模块，**整个进程的三轮用的都是钉住 SHA 的 agent 代码**；分支切换只影响之后从磁盘读的文件。
- 分支切换后从磁盘读的只有每轮的任务夹具/检查器。`eac798d` 与 `feat/permission-v0.1` 之间 `eval/tasks/` 只差一个文件：`17-write-missing-test/check.mjs`，改动是把「生成的测试没全过」从基础设施错误折成断言失败，对通过的轮次没有影响；17 在三轮都通过。
- 因此通过率与 token/请求/墙钟口径不受影响。**唯一代价是「3 轮都在同一份钉住的树上」这句话不再严格成立**，归档记录在案。

后续要求：**运行器占用工作树期间，别的会话不要在同一个 checkout 上切分支或改文件**。跨天窗口还有两天，最稳的是把 `eval:cross-day` 放在没有并行编辑的时段跑。
