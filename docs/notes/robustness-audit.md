# 稳健性检查记录（2026-11-13）

检查按现有分层展开：Core / 协议、模型客户端、Workspace、CLI / TUI、评测链路。保留完全访问、工具串行和零运行时依赖；修复以外部接口上的失败测试为依据，没有重划模块或加入通用框架。

## 响应读取与连接收尾

- **现象**：SSE 已收到 `[DONE]` 仍等服务端断开；坏 chunk 报错后连接仍打开；HTTP 错误详情需要等完整响应；大响应无限累积。
- **根因**：结束标记被忽略；释放 reader 锁被当成取消；`text()` / `json()` 先读全量再处理。
- **解法**：共用有界字节读取器，提前结束或失败都取消响应；HTTP 详情只读够用的部分，非 JSON 响应统一归入 `ChatResponseError`。
- **防复发**：`test/llm.test.mjs` 用保持连接打开的真实本地 HTTP 端点验证断连、结束标记、异常分类及 JSON / SSE 上限；限制见 ADR-0022。

## 会话状态与 Hook 隔离

- **现象**：修改 `Agent.run()` 返回值会改写下一轮请求历史；前置 Hook 的决定字段 getter 抛错会逃逸到宿主。
- **根因**：返回值直接引用内部消息；决定读取发生在 Hook 的异常隔离范围外。
- **解法**：最终消息返回深拷贝；Hook 回调与决定读取共用异常隔离。
- **防复发**：`test/agent.test.mjs` 验证跨 Run 的历史原文，`test/tool-hooks.test.mjs` 验证失败计数与后续 Hook 仍运行。

## 后台任务日志串扰

- **现象**：同一进程的两个 Workspace 都启动 `job-1` 后，第一份输出被第二份覆盖，游标读出另一个任务的尾部。
- **根因**：文件名只有宿主 PID 与 Workspace 内的任务编号。
- **解法**：每份日志增加 UUID、独占创建，POSIX 下创建权限为 `0600`。
- **防复发**：`test/workspace.test.mjs` 通过两个真实 Workspace 启动后台进程，验证输出与增量游标各自隔离。

## 终端输入完整性

- **现象**：中文按字节分片后乱码；粘贴结束标记拆包后吞掉后续 Enter；CR 多行粘贴提前发送；粘贴前后文或第二段原文丢失。
- **根因**：每块独立转字符串；标记解析无跨块状态；只认 LF；异步整行替换占位提示；提交时清空所有粘贴映射。
- **解法**：`StringDecoder` 保留字符状态，暂存标记前缀，统一粘贴换行；提示作为普通输入按光标插入，提交时原位展开。普通 Backspace / Delete 删除后立即回收原文；readline 的 Ctrl+U / Ctrl+K 等 kill 命令会进入有界 kill ring，对应原文保留到最近 32 次 kill 之内，保证 Ctrl+Y 仍能恢复；被淘汰后回收。仍在编辑缓冲区中的后续粘贴继续保留。历史回填保存原文；外部编辑器成功返回后清空映射，避免占位样式文本被误展开；关闭恢复原始输入流。
- **防复发**：`test/tui.test.mjs` 覆盖逐字节中文 / emoji、起止标记各处分片、三种换行、光标两侧正文、同块两条提交、上键回填、编辑器往返和关闭清理。

## 长会话历史丢失

- **现象**：超过 2000 条内存日志后，后续内容仅在活动区短暂出现，离开尾窗即消失；交替空行也能触发。
- **根因**：裁剪日志头部后，已提交展示行数没有重定位；只数被删条目的行数还会漏掉首部空行的隐式过滤。
- **解法**：按裁剪前后实际展示行数之差调整提交位置，保留 Shell 滚动历史与内存日志的独立语义。
- **防复发**：`test/tui.test.mjs` 用终端模拟器检查跨上限后的早期、中段与末尾输出，包含交替空行。

## 补全缓存与输入历史

- **现象**：小上限缓存影响后续大上限请求；调用方修改结果数组会污染补全；历史只取少量记录却读取整个文件，零条上限也返回旧记录。
- **根因**：缓存键遗漏上限并暴露引用；历史全量读取后切片，`slice(-0)` 等于全量。
- **解法**：缓存区分根目录与数量上限，返回数组副本；历史有界读取尾部并反向扫描，零条立即返回。
- **防复发**：`test/file-index.test.mjs` 与 `test/prompt-history.test.mjs` 验证缓存隔离、返回副本、零条和超大历史切口。

## 评测错误归属与任务池收尾

- **现象**：模型连接失败算成任务失败；任务池已拒绝，其他任务仍继续请求模型；夹具复制失败遗留临时工作区。
- **根因**：分类器只识别底层网络码；`Promise.all` 首错即返回；临时目录清理不在 `finally`。
- **解法**：识别 `ModelConnectionError`；首错停止领取新任务并等待已启动任务结束，再传播首错；成功失败均清理临时工作区（`keep` 例外）。
- **防复发**：`test/eval.test.mjs` 用本地 HTTP 和临时夹具检查分类、轮次结束后无新请求、复制失败无目录残留；没有调用真实模型。

## 验证边界

自动测试的终端模拟不能代替所有真实终端与输入法。Windows 环境下跳过的 POSIX / Linux PTY 用例不作通过声明。完全访问不是沙箱，父目录替换的文件系统竞态等既有边界仍按原 ADR 保留。

本轮验证结果：

- `npm run check`：类型检查通过；411 项测试中 405 通过、6 项平台相关跳过、0 失败，较基线增加 30 项回归测试。
- `npm run eval:check`：20 个任务的初始失败断言自检全部通过，没有调用模型。
- 真实模型只读冒烟：在独立的本地临时工作区读 `smoke.txt` 并返回校验文本；2 次模型请求、1 次 `read`、3314 token，退出码 0。
- `git diff --check`：通过；没有添加依赖、提交、推送或合并。
- 未验证真实交互终端与输入法；完整的真实模型评测未运行。
