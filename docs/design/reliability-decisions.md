# 跨模块可靠性约束：结论与理由

这里仅记录不适合单独建 ADR、但容易在后续重构中反复犯错的长期约束。具体实现以当前代码与测试为准；已由 ADR 定义的行为，以 ADR 为准。

| 当前结论 | 为什么这么做 |
| --- | --- |
| 搜索必须有真实扫描预算、命中上限和「可能不完整」提示；多段 glob 通配符用有界动态规划匹配，不能交给主线程同步回溯正则 | 返回量上限挡不住搜索全盘，回溯正则甚至会在单个文件名上卡住取消 |
| `grep` 正则匹配放 worker，超时取消线程 | 灾难性正则回溯在主线程中无法可靠中断，详见 [ADR-0010](../adr/0010-grep-regex-in-worker.md) |
| JSON/SSE 响应读取量有上限，收到 `[DONE]` 即停止并取消未读响应；HTTP 错误必须保留已确认的状态分类 | 先读全量再截断等于没有读取上限，错误页断流也不能把 401 当网络故障；详见 [ADR-0022](../adr/0022-bound-external-response-and-history-reads.md) |
| 模型响应的角色、终止原因、工具调用配对都必须校验；失败不能假装空成功 | 协议形状不是展示细节，错误数据进入 Transcript 会污染后续步骤 |
| `AGENTS.md` 每次请求前重读，工具说明书对外返回深拷贝，`Agent.run()` 的最终消息与内部历史隔离 | 缓存会让变更后的项目规范失效；共享引用能让外部调用者意外改写内核的实际状态或校验条件 |
| 用户输入、控制字符、方向控制字符要经过统一显示边界；TUI 主视图只展示概要，历史细节用独立视图 | 不可信文本可能改写终端外观；多层活动信息重复展示会让真正的失败被淹没，详见 [展示分层](./display-layers.md) |
| 多行粘贴的原文映射保留到会话结束，但必须有容量上限；单段未闭合粘贴也有上限 | readline 没有公开接口确认旧占位符何时从撤销/剪切历史消失；详见 [ADR-0023](../adr/0023-bound-tui-paste-history.md) |
| 外部编辑器临时文件使用独立目录，路径不直接拼接进 Shell 参数；失败时尽可能清理，并如实报告清理失败 | 空格及特殊字符可能破坏命令解析，固定临时文件名可能碰撞或覆盖用户文件 |
| 评测的结果集合、计数、持久化写入都必须验证后才能报成功；任务池失败后不再领新任务，等待已开始任务收尾 | 单看 `total` 或进程退出码会让缺失成绩的任务被误报满分；未收尾的任务会继续消耗模型额度 |
| 回归测试验证**可观察结果**，不仅验证按键、入口、Hook 被调用；断言放在会吞异常的 Hook 外部 | 「入口被触发」不证明用户看到正确结果；测试断言被故障隔离吞掉会出现假绿 |

## 当前已知边界

- 单目录的补全索引与评测诊断快照仍可能一次枚举大量文件；不能声称绝对有界内存。
- 部分 SSE 端点的多行 `data:` 事件、POSIX FIFO 打开时的阻塞、非 UTF-8 后台输出以及文件系统父目录替换竞态，尚不能宣称完全处理。
- 模拟终端测试无法代替全部 Windows Terminal、Linux PTY、输入法和终端组合字符行为。
- 评测检查器的已知漏检单独列在 [评测说明](../../eval/README.md)；历史 100% 通过率不是严格需求覆盖率的证明。
