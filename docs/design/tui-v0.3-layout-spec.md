# agent-Kernel TUI v0.3：字符布局与视觉验收规范

> 状态：设计与验收文档（不是现有实现说明）
>
> 目标分支：feat/tui-v0.2（PR #9）
>
> 适用范围：现有 TUI 的布局和显示层；不修改 Agent Loop、Permission 执行策略、Session 语义或工具协议。

## 0. 背景与总原则

当前 Windows PowerShell 截图中，标题位于顶部、对话内容沉在窗口底部，大块空白夹在两者之间；输入提示缺少清晰边界，工具调用与正文层次不足。此文档把「像 Claude Code 那样清晰、可读的终端聊天界面」转成可逐项验收的规则，而不是只要求模仿若干颜色或图标。

**最重要的三条：**

1. **对话从顶部开始**：在对话视口内从上往下排列，内容不足一屏时绝不加顶部填充把它推到最下面。
2. **输入框跟随会话进度**：内容少时靠近当前对话，内容多时停靠底部；输入框始终独立且不能被模型输出覆盖，权限与统计始终在其下方。
3. **工具与审批易读且安全**：正文、工具状态、拒绝理由清晰区分；审批不能截断或改写实际命令。

以下代码块是**等宽字符布局规格**，不是需要逐字硬编码的静态屏幕。实际宽度、高度要随终端变化。

## 1. 空会话：启动后

~~~text
 agent-Kernel                                      hy3
 E:\JavaProjects\web-project\agent-Kernel
 ─────────────────────────────────────────────────────












 ┌───────────────────────────────────────────────────┐
 │ ❯ Ask anything, or type /help...                  │
 └───────────────────────────────────────────────────┘
 workspace-write                0 requests · 0 tokens
~~~

验收要点：

- 顶部两行显示项目名称、模型和当前工作目录，然后是一条细分隔线。
- 新会话的对话视口为空；不要输出整屏 help、调试日志或启动 banner。
- 空会话和短会话的输入框紧跟 Header 或最新消息；长会话底部停靠，始终保留清晰的上下边界和 Permission / 统计信息。
- 未输入文字时提示文案是占位符，不应进入 readline 的实际输入缓存，也不能影响光标和输入法。
- 无颜色终端也要能辨别头部、输入和状态；不依赖终端背景必须是黑色。

## 2. 日常聊天：短回复必须贴顶

~~~text
 agent-Kernel                                      hy3
 E:\JavaProjects\web-project\agent-Kernel
 ─────────────────────────────────────────────────────

 ❯ 请读取 README.md，并总结这个仓库。

   ● Reading README.md
   ✓ Read README.md

 ✻ 这是一个轻量级 Coding Agent 项目。

   它包含 Agent Loop、七个工具、三档权限，
   以及 Session 和终端交互界面。








 ┌───────────────────────────────────────────────────┐
 │ ❯ Ask anything, or type /help...                  │
 └───────────────────────────────────────────────────┘
 read-only                    2 requests · 6,028 tokens
~~~

重要：上例中 README.md 和回答只是示意内容，并非对当前仓库运行结果的断言。

**必须实现的排列行为：**

- 用户消息从对话视口的第一行开始，之后按时间顺序排列工具调用和模型回复。
- 对话内容未填满视口时，**空白在下方，不在上方**。严禁再使用 top padding 把历史「贴底」。
- 用户用「❯」、模型用「✻」表示；传统终端可退化为「>」和「*」。
- 用户消息与 AI 回复之间有一行左右的视觉留白；不要把每个事件都挤在相邻文字行里。
- 长回答自然换行，续行缩进与正文保持一致，中文、英文与路径混排不能撕裂边框。
- 不在正文中打印重复的「model:」等标签，也不要重复显示同一条 Tool call。

## 3. 等待模型时

~~~text
 ─────────────────────────────────────────────────────

 ❯ 帮我检查 src/agent.ts

 ✻ Thinking...









 ┌───────────────────────────────────────────────────┐
 │ ❯ Ask anything, or type /help...                  │
 └───────────────────────────────────────────────────┘
 workspace-write                1 request · 850 tokens
~~~

- 「Thinking...」只表示等待模型返回；不要假称展示模型内部思考过程。
- 第一段正文、工具调用或错误出现后，等待提示应立即替换或消失。
- 每次模型请求可重新显示等待状态，但不向历史里反复追加不可清理的占位文本。
- 流式正文要平滑更新，不应持续清空整屏造成肉眼可见的闪烁。

## 4. 工具事件与错误

~~~text
 ❯ 检查这个文件

   ● Read src/missing.ts
   ✗ Read failed
     File not found: src/missing.ts

 ✻ 这个文件不存在，我先检查目录。

   ● List src/
   ✓ Found 8 entries
~~~

- 工具状态分为：执行中、成功、执行失败、权限拒绝、未执行（取消或预算阻止）。
- 状态图标使用低干扰配色；无颜色时也能依靠符号和文字理解。
- 错误理由至少显示有意义的第一段；过长时允许摘要，并要提供查看完整文本的方式，而不是悄悄抹掉关键原因。
- 不能把「权限拒绝」显示成「执行失败」，不能把「审批通道关闭」说成「用户选择拒绝」。
- 对 write/edit 等工具优先显示路径和结果，不要把整份文件内容刷进聊天区域。

## 5. Shell 审批：完整命令 + 单次授权菜单

~~~text
 ❯ 帮我运行测试

   ● Shell: npm run check

 ─────────────────────────────────────────────────────
 Shell permission
 Workspace: E:\JavaProjects\web-project\agent-Kernel

 Command:
   | npm run check

 Do you want to proceed?
   1. Yes, allow once
 ❯ 2. No (default)

 Esc to cancel
 workspace-write               2 requests · 1 tool call
~~~

- 默认高亮 **2. No**。空回车按当前选中项确认，因此默认拒绝；只有上键选中 **1. Yes, allow once** 后再按 Enter，才允许本次命令。固定 TUI 不再显示文字输入行，粘贴 `1`、`y`、`yes` 不得产生隐形授权。
- 下键选中 No，Enter 拒绝；Esc 直接拒绝；**不提供永久授权 / 不再询问**。审批期间隐藏普通聊天输入和状态栏，结束后恢复光标与原有输入；非固定布局仍使用可见的 y/N 提示。
- 传统终端、无固定布局时继续原有逐行 y/N 提示；不得把普通输入行当成持久授权。

**安全不变量：**

1. 显示的必须是**将实际执行的完整命令**和真实 cwd，不得只显示前 160 个字符。
2. 多行命令按原有行边界逐行展示，不将换行压成普通空格；控制字符、终端控制码和双向文本控制符必须安全转义。
3. 命令长到超过一屏时，必须允许查看全部内容（例如审批视口内滚动）；**不允许隐藏危险尾部后仍允许直接确认**。
4. 允许只作用于当前一次 Shell 调用；下一次审批必须重新默认选中 No，不能缓存批准。
5. Ctrl-C、EOF、无 TTY、取消与审批通道错误保持现有 fail-closed 行为，不得卡死。
6. 审批只负责询问；真正的工具权限检查仍在 ToolRegistry.execute()，不能因为 UI 改造绕过它。

## 5.1. Claude Code 实机对照补充：自适应输入框（2026-11-06）

此前字符图将输入框固定在窗口底端；真实 Claude Code 的短会话输入区紧跟当前对话，空白留在输入区下方。为减少短会话中间的大块留白，最新交互规定：

- 空会话：输入框紧跟 Header 的分隔线下方；短回复：输入框紧跟最新消息下方，留一行呼吸空间。
- 历史内容接近一屏后：输入框和状态行自动停靠窗口底部；PageUp 浏览历史时继续保持稳定的底部输入。
- 审批时：两项菜单与键盘确认提示尽量紧贴完整命令；长命令超过可视高度时仍可翻页查看，不得截断授权内容。
- 这属于**纯显示布局**变化，不调整输入文本、Permission、审批结果或 Agent Loop。旧固定底部模式保留为显示层兼容选项。

本轮根据同尺寸 Claude Code 实机截图继续细化：日常输入区使用两条灰色水平分隔线，取消四角和左右竖线，正文、提示符与分隔线共享左边缘；上面的四边框字符图仅保留为早期概念图。占位符仅在空会话出现。现代终端在当前会话内使用稳定块状光标，退出时恢复默认光标样式，不改终端持久配置。

等待时以动画强调色符号与主状态、灰色经过秒数、次行取消提示区分层级。工具运行子行随结果替换消失，待审批时不显示为正在执行；完成后显示本次真实耗时与工具调用数。现有 UI 事件没有模型思考正文，不能用模拟文字补齐 Claude 的思考详情。
- 下方字符图中的“固定底部”位置适用于**长会话停靠态**，不是短会话启动态。

## 6. 界面区域与滚动约束

~~~text
 ┌─────────────────────────────────────────────────────┐
 │ HEADER                                              │
 │ project · model · workspace                         │
 ├─────────────────────────────────────────────────────┤
 │ CONVERSATION VIEWPORT                               │
 │                                                     │
 │ ❯ User message                                      │
 │   ● Tool in progress                                │
 │   ✓ Tool finished                                   │
 │ ✻ Assistant reply                                   │
 │                                                     │
 │ Content flows TOP -> DOWN                           │
 │ Empty space stays BELOW the messages                │
 │                                                     │
 ├─────────────────────────────────────────────────────┤
 │ INPUT                                               │
 │ ❯ Ask anything, or type /help...                    │
 ├─────────────────────────────────────────────────────┤
 │ STATUS: permission · requests · tools · tokens      │
 └─────────────────────────────────────────────────────┘
~~~

- **Header 固定顶部；短会话时输入框与状态行跟随内容；长会话或历史滚动时它们停靠底部；中间仅对话视口滚动。**
- 内容不满一屏：起点永远是视口顶部；内容超过视口：自动跟随最新输出，直到用户手动滚动查看旧内容。
- PageUp/PageDown 浏览历史后，不能打断已输入的文字、光标位置与输入法组合状态。
- 当用户在查看旧消息时，新的模型输出不应强行把视口拉回底部；可以提示有新内容。
- 终端 resize 应重算布局、宽度和换行，不丢会话内容。
- 窄终端或不支持完整控制序列的终端提供可读的简化布局；不得丢失审批详情。
- 普通运行日志不应写进固定输入区域，避免覆盖正在编辑的命令。
- 保留真实会话语义：/permission、/reset、/help、/exit 继续有效。

## 6.1 Slash 命令补全（2026-11-07）

用户在空闲的聊天输入框键入 `/` 时，紧贴输入框下方显示命令列表，顺序是 `/help`、`/permission`、`/reset`、`/exit`、`/quit`。所有命令均为已经实现的 CLI 命令；不实现或显示 Claude Code 的 `/compact`、`/branch` 等额外功能。

~~~text
─────────────────────────────────────────────────
❯ /
─────────────────────────────────────────────────
❯ /help           Show available commands
  /permission     View or switch permission mode
  /reset          Clear the current conversation
  /exit           Exit agent-Kernel
  /quit           Exit (alias of /exit)
workspace-write                     0 requests · 0 tokens
~~~

- 输入如 `/per` 实时筛选；上下键改变选中项；`Tab` 只补全到输入框、不执行；`Enter` 提交当前高亮的命令；`Esc` 只关闭菜单并保留草稿；输入发生改变可重新展开。
- 使用现有 readline 编辑缓冲；菜单方向键不能覆盖历史任务，不能改动已有输入草稿，不向模型或 Transcript 添加菜单行。
- 命令带参数（如 `/permission read-only`）时关闭候选列表并按原来的命令解析执行；未知命令不被改写。
- 列表跟随中英文 UI 显示描述，但命令名称、执行逻辑不翻译。
- 布局在小屏幕和窗口 resize 下保留标题、输入、状态及有限菜单条目，不覆盖 Shell 审批。无 TTY/非固定布局沿用原有逐行输入。

## 6.2 中英文自动适配（2026-11-07）

- TUI 启动时界面默认为英文；每次用户提交自然语言任务后自动检测该任务的主要语言（中文 / 英文），作为后续界面文案的语言，直到下一次有可判断语言的用户任务。Slash 命令、工具结果与模型输出不触发语言变化。
- 仅本地化 TUI 自身生成的菜单、工具操作标签、运行状态、统计、权限与帮助文案；路径、文件名、Shell 命令、工具原始错误、模型回复、权限模式标识保持原文。
- **`Thinking...` 是固定字样，不翻译**；前置动画、计时和清除行为均保持不变。辅助提示（如 `Ctrl-C to cancel`）可翻译。
- 混合中英任务通过轻量启发式选择主要语言，识别不保证能理解语义；不引入模型语言识别、设置开关或额外依赖。界面切换只对新产生的状态和菜单生效，历史内容不追溯翻译。

## 7. 色彩、兼容性与实现范围

- 优先在 Windows Terminal / VS Code 终端验收现代 Unicode + ANSI 配色；传统 Windows PowerShell conhost 保留 ASCII 降级，禁止出现乱码方框。
- 颜色仅表达层次：标题与输入提示用少量强调色，用户正文用中性粗体，普通输入边界用灰色；模型正文中性高对比；工具成功柔和绿色；失败红色；权限审批黄色。待审批面板完整展示命令与 cwd，回答后收起面板，保留允许一次/拒绝决定及工具结果。
- 终端底色由终端主题控制。程序可以在 ANSI 兼容终端设置文字和局部样式，但**不能承诺自动把传统 PowerShell 蓝色背景变成 Claude Code 的深灰主题**；截图验收时应明确终端及配色设置。
- 优先改现有 src/tui.ts 与相关显示测试，不另起一个 TUI 框架；运行时保持零依赖。
- 不修改 Agent Loop、不更改 tool schema、不改变 Permission、Transcript、Session、审批和取消链的执行语义。
- 本轮不做鼠标、多面板、复杂命令补全或 Hooks。先解决基本阅读和输入体验。

## 8. 验收清单（不能只看字符串测试）

在真实 Windows Terminal 和传统 PowerShell 中手动核对以下场景：

- [ ] 空会话：Header 位于顶部，输入框与状态行紧接其下，无需把光标放到屏幕最底端。
- [ ] 单轮短回复：用户提问、工具调用、AI 回复都**从对话区域顶部开始**，下方留白。
- [ ] 多轮回复：按时间顺序展示，无重复工具事件，权限和 Token 统计正确。
- [ ] Thinking -> 第一段流式文本 / 第一个工具调用：等待提示及时清除，无闪屏。
- [ ] PageUp/PageDown 历史滚动：输入中的文字和光标仍正确。
- [ ] 缩小、放大终端窗口：中文、长路径、边框和输入行没有错位。
- [ ] Shell 审批：单行、多行、超长命令、控制字符都完整安全展示；允许与拒绝行为正确。
- [ ] Ctrl-C / EOF / 无 TTY：保留拒绝、取消和退出行为，不能挂住。
- [ ] 传统 PowerShell：ASCII 字符和无颜色降级仍可读。
- [ ] 运行 npm run check、npm run eval:check；Linux/Windows CI 通过。

推荐用固定任务进行人工截图验收：

~~~text
请读取 README.md，并用一句话总结这个仓库，不要修改任何文件，不要运行 shell。
~~~

**交付必须包含**：实际终端截图（至少空会话、短回答、审批三种）、测试结果、已知显示局限、提交 SHA 和 PR 链接。没有运行过的环境必须诚实注明“未验证”，不能用伪造截图替代。
