# ADR-0026：read 支持行窗口、grep 接受单个文件，未知参数按工具收紧

- 状态：已采纳（2026-11-16）
- 影响范围：`src/tools/workspace.ts`、`src/protocol/types.ts`、`src/core/tool-registry.ts`、测试与文档

## 背景

第 6 课的子 Agent 在复杂调查任务里反复把 100000 token 预算跑光。日志把原因指得很清楚：

```text
read {"path":"src/tools/subagent.ts"}                  ← 拿到开头 8000 字
read {"path":"src/tools/subagent.ts","offset":150}     ← 又拿回同样的开头
read {"path":"src/tools/subagent.ts","offset":194}     ← 还是同样的开头
grep {"pattern":"…","path":"src/tools/subagent.ts"}    ← ERROR: parent path is not a directory
```

两件事同时在坑里：`read` 根本没有 `offset`，多余参数被静默忽略，模型以为在翻页；`grep` 只收目录，模型想「就在这个文件里搜」时要先失败一次再改路径。**模型没有做错什么，是工具在骗它。**

## 决定

- `read(path, { offset, limit })`：按行读窗口，`offset` 从 1 起。不传参数时走原来那条路，输出与截断文案一字不变（老行为不能因为新参数漂移）。
  - 行号必须从文件头顺序数（文本文件没有行索引），所以按 64 KB 分块读、边读边数行，只保留「未结束的那一行」和目标窗口；峰值内存不随文件大小增长。
  - **窗口同时受行数和字符预算约束**（`MAX_OUTPUT_CHARS` 减去尾注预留）。只按行数收会漏行：100 行可能是两万字，`clip` 一截模型只看到 40 行，而下一段却按第 101 行提示 —— 中间 60 行永远读不到。字符预算必须在窗口里生效，`lastLine` 只数真正交出去的行。唯一例外是单行本身超预算：那一行照样给出（由 `clip` 截断并标明），下一段从它的下一行开始，仍然不漏行。
  - 为了定位行号最多往后扫 8 MB；扫不到就明确说「offset 没走到」，绝不说成「文件就这么长」。
  - 行尾原样保留（不剥 `\r`）：模型常把读到的片段直接拿去 `edit` 精确替换，少一个 `\r` 就匹配不上 CRLF 文件。
  - 读中间时告诉模型下一段从哪个 `offset` 继续；读到末尾不谎称「后面还有」。
- `grep(pattern, path, …)`：起点可以是目录（递归）或单个文件（只搜它自己）。搜索逻辑抽成同一个闭包，单文件与多文件走同一条路，避免以后只改一边。
- 未知参数：`Tool` 增加可选 `strictArguments`，在 `ToolRegistry` 校验参数时拒绝未声明字段并列出可用参数。**默认关闭**，只对 `read` / `write` / `edit` / `glob` / `grep` / `ls` 打开。

## 取舍与边界

- **不全局收紧未知参数。** Worker 的 `shell` 包装层刻意吞掉 `background` 并强制前台，靠的就是「多余字段不报错」；全局拒绝会把这条安全约束变成一次报错，子 Agent 反而拿不到「前台执行」的行为。所以做成按工具打开。
- **行窗口不返回行号前缀。** 加了前缀，模型复制片段去 `edit` 就会带上行号，反而更容易改错。
- **不提供「读整个文件」的旁路。** 8 MB 扫描上限和 8000 字符输出上限都保留：`limit` 管「返回多少行」，`clip` 管「返回多少字符」，两条闸门互不替代。
- **已知边界**：行号以读取当时的内容为准，不是快照隔离；文件在读取过程中被改写，窗口可能错位。`grep` 单文件路径若指向特殊文件（socket 等）会明确报错，不会静默返回空结果。
