# ADR-0021：工具调用日志是「显式开启的 JSONL 追加文件」

- 状态：已采纳（2026-11-13）；「敏感信息」一节于 2026-11-28 修订为尽力脱敏 + 受控权限
- 影响范围：`src/core/tool-log.ts`（新增）、`src/cli.ts`（装配）、环境变量 `AGENT_TOOL_LOG`

## 背景

[ADR-0020](./0020-tool-hooks-live-in-the-registry.md) 把 Hook 机制做出来了，但生产代码一个 Hook 都没登记。
机制有没有用，只能拿一个真实需求去试。第一个需求是：事后能查「哪次工具调用、成没成、为什么失败」——
现在这些信息只存在于屏幕上的运行记录里，滚过去就没了。

## 决定

- `createToolLogHooks(file)` 造两个后置回调（成功、失败），返回**登记项**（`ToolHooksOptions`），
  不返回现成的 `ToolHooks`：调用方要能把它和别的事件拼起来再 `new ToolHooks(...)`。
- 每执行完一次工具调用，追加一行 JSON：`ts` / `tool` / `id` / `ok` / `args` / `detail`。
  成功与失败字段完全一样，读日志时不用分情况。
- `ok` 复用 `isToolResultFailure`（和 CLI / TUI 标 ✗ 的同一套判断）：`shell` 非零退出、超时、
  取消都算失败。只看「有没有抛异常」会把一条 `exit 3` 的命令记成成功，事后复盘结论正好相反。
- 只有设了 `AGENT_TOOL_LOG=<路径>` 才登记；不设就完全不写，行为与之前一字不差。
- 写盘用同步追加（和输入历史 `ui/prompt-history.ts` 同一套做法），父目录不存在就建。
  POSIX 上新建文件用 `0600`，已有文件在每次写入前收紧到 `0600`（`openSync(..., 0o600)` + `fchmodSync`）；
  Windows 忽略 POSIX mode，权限交给 NTFS ACL。
- 写不进去**不抛**，只在第一次往 stderr 说一句，之后闭嘴。

## 为什么不是「总是写」

一个默认打开的日志文件是用户没要求过的副作用：它会在工作区或家目录里悄悄长文件，
而且没有任何开关能关掉。显式开启的代价是「用户得知道有这个变量」——写在 README 配置表和启动横幅里就够了。

## 为什么不做日志轮转、查询、结构化级别

一个只追加的 JSONL 文件已经能被 `jq`、`grep`、脚本直接读；轮转和查询是另一件事，
加进来就要回答「保留几天」「按什么切分」，而这些问题现在没有真实需求。

## 敏感信息：从「记录原文」修订为「尽力脱敏 + 受控权限」

**历史决定（2026-11-13）**：日志记录原文，不做脱敏，靠文档提醒用户把日志放在受控位置。
当时的理由是「脱敏规则一旦猜错，日志就会在最需要它的时候变得没用；正确的做法是别把日志放在不该放的地方」。
这段记录保留在这里，避免抹掉当初的取舍；**它已被 2026-11-28 的修订取代**。

**现行决定（2026-11-28）**：API Key、环境变量和密码不应该以明文持久化，所以先做一层尽力脱敏，再用文件权限兜底。
脱敏覆盖两处：

- **按字段名递归**：`api[_-]?key`、`access[_-]?token`、`refresh[_-]?token`、`password`、`passwd`、`secret`、
  `authorization`、`cookie`、`credential`、`private[_-]?key`、`client[_-]?secret` 命中时，整个值换成 `[REDACTED]`。
  嵌套对象和数组逐层处理。
- **按字符串形态**：`Bearer` / `Basic` token、常见前缀（`sk-`、`ghp_`、`github_pat_`、`npm_`、`glpat-`、
  `xox[baprs]-`、`AIza`、`ya29.`、`AKIA`）、`NAME=value` / `NAME: value`（保留名字、只换值，覆盖
  `OPENAI_API_KEY=…` 这类 shell 命令和 `.env` 内容）、以及 PEM 私钥块。

**已知边界（不要把它当成安全边界）**：

- 脱敏是**尽力而为**，正则认不出的格式、编码过的内容、多行拼装的密钥都可能原样落盘；它不是安全边界，不能替代受控目录。
- 字段名 `secret` 会顺带命中 `secretary` 这类普通词，属于有意的过度覆盖。
- 参数与结果各自截断到 2000 字符；递归深度上限 8 层，数组与对象各保留前 100 项。
  超限处会留下 `[MAX_DEPTH]`、`[+N more items]`、`[+N more keys]` 标记，不再静默丢弃。
- 日志仍然可能包含命令、文件正文和其他敏感内容。`AGENT_TOOL_LOG` 应指向权限受控的位置，不要提交进仓库；
  POSIX 上文件权限固定为 `0600`，Windows 上由 NTFS ACL 决定。

## 代价与不变量

- **代价**：开启后每次工具调用多一次同步 open / write / close（毫秒级，远小于工具本身），
  POSIX 上再加一次 `fchmod`；单行最长约 2 × 2000 字符（参数与结果各自截断）。
- **不变量**：工具结果、`ERROR:` 文案、Transcript、模型请求体都不因日志改变；日志 Hook 抛错也只记
  `ToolHooks.failureCount`。
- **已知缺口**：被前置 Hook 拦下的调用不留记录 —— 它没有执行，也就没有结果事件。
  要审计「谁想跑但被拦了」，得让前置 Hook 自己写。
- **已知边界**：日志路径不做校验，写不进去靠 stderr 那一次提醒；不检查路径是否在工作区内（全访问模式，日志本来就可以放在任何地方）。
