# grep 做字面搜索，不做正则

> 已被 [ADR-0010](./0010-grep-regex-in-worker.md) 取代（2026-11-05）：恢复正则的前提「worker + 可中断超时」已经实现。本文保留为那一阶段的取舍记录。

第一阶段把 `grep` 从「按正则在主线程匹配」改成「按字面字符串匹配」。

理由：正则由模型提供，而匹配同步跑在内核主线程上。一条灾难性回溯的模式（`(a+)+$`）就能让整个 agent 卡死，用户只能 Ctrl-C；「单文件 1 MB + 扫描预算」限制的是输入规模，拦不住指数级的匹配时间。字面搜索从结构上消除了这类输入。

代价：失去正则能力。模型传 `a.*b` 会被当成这五个字面字符，找不到时它得换个写法或改用 `shell`。所以工具描述和参数名（`text` 而不是 `pattern`）都写明「不是正则」，别让模型以为传的是模式。

要恢复正则，前提是把匹配放进 worker 并带可中断的超时，而不是把 `new RegExp` 加回来。同一次修改还给超长行的截断加了显式标记，避免模型把截断后的 200 字当成整行。
