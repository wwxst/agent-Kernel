# TUI 多行粘贴历史采用有界会话归档

## 决定

- 每段多行粘贴使用会话内唯一占位符；原文映射保留到 TUI 关闭，不根据 readline 的私有 undo / redo / kill ring 状态猜测何时可以回收。
- 会话归档最多保留 32 MiB 原文（按 UTF-16 码元数乘 2 估算）或 256 段多行粘贴；任一上限先到就拒绝新的多行粘贴，并显示明确警告。
- 已接受的粘贴不会被截断；关闭 TUI 时清空归档，重新打开后额度重置。

## 理由

Node readline 没有公开接口告诉调用方某个占位符是否仍存在于 undo / redo 快照或 kill ring 中。编辑次数不等于快照淘汰：反复 undo / redo 可以在不淘汰旧快照的情况下改变当前行；kill ring 还会抑制与顶部相同的重复剪切。依赖这些近似计数会让用户恢复出占位符，却找不到原文。

读取 readline 私有 Symbol 虽然能窥探当前 Node 实现，但它不是稳定 API；版本升级后可能静默失效。会话级归档配合硬上限，不依赖内部实现，也不会在撤销、重做、剪切恢复或外部编辑器往返时丢失原文。

## 代价与边界

- 已经不再需要的粘贴原文也会保留到 TUI 关闭；原文占用上限为 32 MiB，另有最多 256 个 Map 条目的固定元数据开销。
- 达到任一上限后，新多行粘贴会被整体拒绝并提示；不会静默截断，也不会把粘贴内容拆成多条任务。用户需要关闭并重新打开 TUI 后继续。
- 32 MiB 按 JavaScript 字符串的 UTF-16 码元估算，不是 V8 堆总量的精确上限；条目数上限同时约束 Map 元数据。

## 不变量

- 已接受的多行粘贴在当前 TUI 生命周期内始终能由唯一占位符恢复。
- readline 的 undo、redo、kill ring 和外部编辑器可以恢复旧占位符；编辑器正文里普通的提示样式字符串不会与唯一编号冲突。
- 不新增运行时依赖，不读取 readline 私有状态，不改变 Agent Transcript 或模型请求格式。
