# grep 在 worker 里做正则匹配

`grep` 从「字面搜索」（[ADR-0009](./0009-grep-is-literal.md)）改回「正则搜索」。前提条件不是把 `new RegExp` 加回主线程，而是 ADR-0009 写好的那条：匹配放进 worker，带可中断超时。

## 决定

- 每个 `grep` 调用起一个 worker（`src/grep-worker.ts`）；worker 只做逐行 `test()`，遍历、读文件、截断、排序仍留在主线程。
- 主线程只守一个匹配时间预算（`regexBudgetMs`，默认 2 秒），且只统计匹配时间，不把读文件算进去。
- 超时或取消直接 `terminate()`：回溯是同步循环，没有别的方式让它自己停下来。
- 超时不抛失败，而是停在当前文件、保留已经收集的命中，尾注写明 `regex stopped after 2000ms; results may be incomplete`。
- 工具参数从 `text` 改回 `pattern`，并增加 `flags`（只接受 `i/m/s/u`，`g`、`y` 忽略）。`fixed=true` 把 pattern 转义后走同一条匹配路径，给搜 `a.b`、`([` 这类字面文本留一个不用记转义的入口。

## 理由

字面搜索的代价是模型拿不到正则：`a.*b` 被当成五个字面字符，找不到时只能换写法或改用 `shell`。现在 worker 把「匹配」和「调度」分开，主线程的取消和超时仍然有效：

- 一条 `(a+)+$` 在 1 MB 文件上是 2^40 级回溯，但线程可以被 terminate，主线程在 2 秒内拿回控制权；
- 预算按「匹配花了多久」算，慢磁盘不会挤掉正则的时间；
- 部分结果如实标注，模型能判断「没搜到」还是「没搜完」。

## 代价

- 每次 grep 多 ~30ms 的线程启动和一套消息协议；worker 崩溃要折成 `ERROR`，不能留下永不 settle 的 promise。
- 正则语法进入了工具接口：坏正则不再「静默不命中」，而是 `ERROR: invalid pattern`，模型得改写法。
- 结果可能因预算而部分缺失，依赖尾注说清楚。
- 新增 `src/grep-worker.ts` 一个文件；它不依赖任何模块，只被 `workspace.grep` 拉起。

## 不变量

**输入不能让 agent 卡死。** 这条现在由「匹配不在主线程 + 超时 terminate」保证，而不是由「只支持字面」保证。后续如果要再放宽（比如允许多文件并行匹配），必须先保住这条。
