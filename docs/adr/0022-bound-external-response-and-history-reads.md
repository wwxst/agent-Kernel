# 模型响应与输入历史使用有界读取

## 决定

- JSON 与 SSE 共用响应读取入口，单次最多接收 8 MiB 解压后的响应体字节；包括 SSE 注释、元数据和未换行内容。超限抛 `ChatResponseError`，不返回半截成功。
- SSE 收到 `[DONE]` 后停止读取；无论完成、解析失败或超限，都取消未读响应并释放 reader。
- HTTP 错误详情够 500 字符即停止读取，保留 HTTP 状态分类。
- 已收到 HTTP 状态后，即使错误页断流，也保留 HTTP 分类；用户取消仍传播取消。
- `AGENTS.md` 每次模型请求前重读，实际读取最多 8 MiB，另探 1 字节确认截断；正文仍最多 32000 字符，两个上限任一触发都明确提示。
- 输入历史只读取文件末尾最多 8 MiB，从后向前找最近的有效记录；从文件中间开始时丢弃首个残行。历史文件不改写、不轮转。

## 理由

`max_tokens` 是给服务端的请求参数，不能保证实际响应有界。先 `response.text()` / `response.json()` 再截断，仍然已经读取了全部内容；单独释放 reader 锁也不能停止未读响应。

历史文件只追加，长期使用后会不断增长。为了显示最近 500 条输入而同步读取全部历史，会让启动时间与内存消耗持续增加。

## 代价与边界

- 单次超过 8 MiB 的模型响应现在明确失败；需要更大的合法响应时应调整集中常量，不增加新的 CLI 配置层。
- 极大的历史记录或大量坏行可能让读取窗口内不足 500 条；窗口外的旧记录仍留在磁盘，不参与此次加载。
- 项目指令中超过 8 MiB 的内容不参与当前请求，包括极端空白前缀之后的正文；普通文件按原有 trim 与字符上限处理。同步打开特殊设备的时间界限不在此保证内。
- 响应上限约束的是累计读取量，不是 V8 堆的精确上限；解码、JSON 解析和消息拼装仍会产生有界的中间副本。
- 历史读取窗口不限制磁盘文件大小；后台任务日志和调用日志的轮转仍由用户负责。

## 不变量

- 合法响应仍走原来的消息与 usage 校验；取消不伪装成成功。
- 流式增量仍只用于显示；工具串行、预算、完全访问模式不变。
- 不添加运行时依赖，不改变历史存储格式。
