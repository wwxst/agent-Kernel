# 这是 Trusted Local Coding Agent，不是沙箱

`WORKDIR` 只是工具的默认 cwd 和路径校验的基准，不构成操作系统级隔离：`shell` 一条 `cd ..` 就能出去，子进程的读写权限和启动它的人一样。Permission v0.1 的三档策略同样只是工具调用策略，不是隔离，见 [ADR-0013](./0013-permission-is-a-policy-not-a-sandbox.md)。

选择：把它定位成「在你自己的机器、你自己的项目里跑」的单人工具。路径守卫、真实路径校验、输出上限，拦的是模型手滑和意外，不是恶意代码 —— 所以它们值得做，但不能拿它们当安全保证。真要隔离，方式是用容器、虚拟机、独立用户或只读挂载去跑它，而不是继续往这里的字符串校验上加判断。

代价：这个 agent 不适合跑不受信任的仓库或不可信的 prompt 注入内容。换来的是一条说得清的边界，而不是一份「看起来安全」的检查清单。
