# TUI 改在主屏就地渲染，保留 Shell 历史

现状（v0.3 + #34）：`--tui` 在交互终端里进入**备用屏幕**（`ESC[?1049h`），进去是一块空白屏，退出时用 `ESC[?1049l` 把原来的画面还回来。好处是布局稳定、每帧整屏重绘（`ESC[2J ESC[H`）不会把中间帧写进 Shell 滚动历史、退出后终端干干净净。

问题：用户在 TUI 里看不到打开之前敲过的命令和输出。对照 Claude Code，它是**不切屏**的——直接在主屏上往下打印，历史一直悬在上面，往上滚就能看到刚才的对话。

## 决定

TUI 改在主屏就地渲染，不再进入备用屏幕：

- **已收尾的历史行直接打印**进终端的 scrollback（真输出，之后不再重绘）。
- **只有底部可变区**（正在流式输出的正文、运行中的工具行）和**输入区 chrome**（上边框、输入行、下边框、状态行）原地重绘。
- 每帧只做「追加已提交行 + 清掉可变尾部 + 重画尾部与 chrome」，不再整屏清空。

## 为什么

用户明确要求「打开时之前的输入还在」，并且已经知道备用屏只是把内容藏起来、退出后历史不丢。用一个看不见上下文的界面换布局稳定性，这笔账不划算；而且备用屏下终端原生滚动、复制、搜索全都用不了，只能靠我们自己实现的 PageUp/PageDown 看 2000 行内存日志。

## 代价与边界

- **失去应用内翻页**：`PageUp` / `PageDown` 不再由 TUI 接管，回看历史交给终端原生滚动。日志上限 2000 行仍在内存里，但屏幕上的历史和它不再等价。
- **失去鼠标点击展开**：现在的 `▸/▾` 靠 SGR 鼠标事件 + 绝对坐标定位单元格；主屏下鼠标事件不再独占（终端自己的选择、链接都要能用），这个交互需要重新设计或去掉。
- **失去顶部固定标题行**：`title` / `path` / 分隔线会随历史一起往上滚走，不再常驻第一行。状态信息保留在底部状态行。
- **resize 不重排历史**：宽度变化时已打印的行由终端自己折行，TUI 只按新宽度重画底部可变区和 chrome。
- **退出必须清干净**：清掉底部 chrome、光标落到新行，不能留半截输入框。
- **闪烁风险**：可变尾部每帧「清掉再重画」，流式输出时可能出现轻微抖动，需要用同步更新序列（`ESC[?2026h/l`）包住整帧。
- 不是沙箱，审批的逐次询问、`y/yes` 判定、默认拒绝都不因显示方式改变。

## 采用业界已有方案（不自己发明）

Claude Code 与 Codex CLI 的做法一致，直接照抄：

| | Claude Code | Codex CLI | 我们 |
| --- | --- | --- | --- |
| 主视图 | Ink + `<Static>`，定稿内容打印一次进 scrollback，只重绘底部动态区 | ratatui inline viewport，底部固定高度区域，其余正常滚动 | 主屏只追加 + 底部活动区重绘 |
| 备用屏 | 主视图不进 | 默认 `auto`，`--no-alt-screen` / `alternate_screen="never"` 可关 | 主视图不进，**只给 transcript 视图用** |
| 看历史 | `Ctrl+O` 打开 transcript 视图（临时接管整屏） | `Ctrl+T` / `/tui` 切 Fullscreen transcript | `Ctrl+T` 打开 transcript 视图 |
| 鼠标 | 不捕获 | 不捕获 | 不捕获 |

**结论：历史永远不可原地修改；要展开、折叠、搜索历史，就切到临时全屏的 transcript 视图里做。** 备用屏不是废弃，而是专门留给这个视图。

## 决定

- **主视图（默认）**：不进备用屏。已定稿的行用普通输出打印进 scrollback（之后不再重绘）；底部保留一块活动区（当前轮可变内容 + 输入框 + 状态行），每帧只重画这块。
- **transcript 视图（`Ctrl+T`）**：临时进入备用屏，复用现有的整屏网格渲染，可以上下滚动、展开/折叠任意轮次；`Ctrl+T` 或 `Esc` 退出，主屏原样还回来。
- **不捕获鼠标**：滚轮、滚动条、选中复制、终端搜索全部保持原生。点击展开取消（业界两家都没做），展开走键盘。
- **删掉主视图的视口逻辑**：`PageUp/PageDown`、滚轮、`scrollOffset`、`resizeAnchor` 只服务 transcript 视图。

## 为什么

用户明确要求「打开时之前的输入还在」。备用屏隔离虽然让布局稳定，但代价是看不见上下文、终端原生滚动和复制全废。业界两家的成熟做法已经证明：**只追加的主视图 + 独立的临时全屏视图**能同时满足「历史可见」和「历史可查」，不需要自己发明折中方案。

## 代价与边界

- **主视图的历史不可改**：已打印的行无法原地展开/折叠，这是终端 scrollback 的物理约束，不是实现缺陷。
- **`Ctrl+O` 已被「展开阶段」占用**，transcript 用 `Ctrl+T`（与 Codex 一致）。
- **resize 不重排历史**：宽度变化时已打印的行由终端自己折行，TUI 只按新宽度重画活动区。
- **退出必须清干净**：清掉底部活动区、光标落到新行，不留半截输入框。
- **闪烁风险**：活动区每帧「清掉再重画」，用同步更新序列（`ESC[?2026h/l`）包住整帧；传统 conhost 上不保证完全无感。
- 不是沙箱，审批的逐次询问、`y/yes` 判定、默认拒绝都不因显示方式改变。

## 不变量

- **输入永远在底部**：活动区紧贴当前输出下方。
- **审批安全不因显示改变而削弱**：完整命令、实际 cwd、默认拒绝、取消链、审批通道关闭的区分保持原样。
- **非 TTY 仍是逐行输出**，不参与这套渲染。
- **Run log 不回灌模型**：它仍然只是 Session 的显示缓冲，不是 Transcript。
- **颜色/字形可缺失**：无颜色、无框线、窄终端、resize 都不能让 TUI 崩溃或吞掉审批。
