# ADR-0029：上下文压缩有界、可追溯、失败不提交

## 决定

- 压缩只在**每次真实业务请求发出前**统一做一次（`Agent.prepareRequest()`），不在 Run 开始、结束和每个工具批次后各压一遍。顺序按「花不花钱」排：工具结果 Snip → 历史摘要 → 装不下窗口时连最新批次也换成预览。
- 体积口径是**整份请求**：系统提示、动态项目指令、技能目录、工具定义、每条消息、工具调用参数与结果。只数正文会系统性低估。
- 两把尺子分开：配了 `CONTEXT_WINDOW_TOKENS` 就按 token 估算（80% 触发、70% 收手，窗口先扣掉输出预留），没配就退回字符预算。token 估算优先用上一次请求的真实 `prompt_tokens` 做比例校准；**不按模型名字猜窗口**。
- 工具结果先动**最早、已被模型读过**的；最新一批在模型读到之前不裁剪。只有整份请求连窗口都装不下时，才走「先存档、再给带路径的有限预览」的例外路径。
- 任何有损裁剪**先存档**。存档失败就不做依赖它的替换。存档落在系统临时目录（`AGENT_CONTEXT_ARCHIVE` 可改），不进仓库、不上传、不写进普通日志。
- 历史压缩用当前模型写一份**结构化交接摘要**（八个固定小节），每次是**替换**旧摘要而不是追加。摘要为空、超长、缺小节、请求失败、取消或候选没有实际缩小时，一律不提交，原上下文保持不动。
- 上下文溢出只在**上游明确说输入装不下窗口**时恢复：更强压缩 → 确认请求真的变小 → 最多额外重发一次；不重跑已完成的工具。压不动就明确报错。

## 为什么这样做

模型无状态，历史越长，每轮重发的成本越高，直到装不下。但「省 token」不能以「Agent 忘了自己在干什么」为代价，所以压缩必须同时满足三件事：省得下来、丢得可查、坏了不提交。

- **只在请求前做**：那些位置重复的是同一件事，而「这次请求装不装得下」只有发出前才知道。分散在多处还容易重复花钱。
- **先量后裁**：没有测量就会在还很宽松的时候压缩（白花一次摘要请求），或者在已经很紧的时候才发现（必然 400）。
- **先工具结果、后历史**：工具结果最占地方、最容易重读，删它的语义损失最小；摘要最贵，也最容易出错，所以放最后。
- **保护最新批次**：模型还没看过的结果被折叠掉，等于让它凭空少看一段输出，接着就会重复执行同一个工具。
- **摘要必须替换**：追加式摘要会一路膨胀，最后只能从头截字数 —— 那等于把最老的约束悄悄删掉。
- **失败不提交**：压缩是把「已知的完整上下文」换成「模型写的摘要」。摘要不合格时提交它，风险高于收益；保持原样至少是已知状态。
- **溢出只认明确信号**：普通 400、网络故障、输出截断都救不了，混进来只会白花一次请求，还会把「请求本身写错了」伪装成「上下文太大」。

## 代价与边界

- **摘要是一次额外的模型请求**，要花钱，也计入 Run 的 token 预算。为了不白花，可折范围小于 2500 字符时干脆不开口（一份合格摘要本身就要一两千字符，替换几百字符是净亏）；摘要长度上限跟着被替换内容走，避免「摘要比原文还长」。
- **连续两次摘要不达标就停止再要摘要**（失败、取消、不合格、没有实际缩小都算）。之后历史不再压缩，长会话最终会以明确的上下文超限错误结束 —— 这是「失败不提交」的直接代价。
- **token 数是估算**，不是分词。有真实用量就用比例校准，没有就按 3 字符/token 保守估；中文与压缩过的 JSON 更密，第一次请求之前可能估偏。
- **摘要能省，但不能保证不漏**。结构检查只能发现「格式不对」，发现不了「漏了一个关键约束」。所以还要靠原文存档、长任务回放测试和真实模型对照。
- **Micro Compact 没有实现**：当前仓库拿不到工具输出的语义类型，对任意代码/JSON/日志去重会改变含义，没有可靠规则时就只做 Snip。
- **存档不自动清理**：目录在系统临时目录下，进程崩溃后仍在，由宿主或操作系统清理；里面可能含密钥与源代码。

## 不变量

- 短对话不产生任何额外模型请求。
- 工具调用与结果永远成对、顺序正确；压缩不制造、也不删除单边的调用或结果。
- 有损裁剪要么能追溯到完整原文，要么明确失败；不静默丢内容。
- 摘要请求不带工具、不算 Step、单独计数，费用照记。
- 上下文溢出最多额外触发一次业务请求，且不重跑已完成的工具。
- 主 Agent 与子 Agent 的上下文状态互不影响。
- 对应行为由 `test/context-compact.test.mjs` 与 `test/agent.test.mjs` 持续保护。
