# ADR-0027：后台任务输出写文件，读取与停止都要可核实

## 决定

- `shell` 的后台进程输出重定向到系统临时目录中的独立日志文件，不由宿主保留 stdout/stderr 管道；父进程关闭所持文件描述符后对子进程 `unref()`。
- 每次任务日志使用独立标识并独占创建，避免不同 `Workspace` 中重名的 `job-1` 相互覆盖；POSIX 日志权限按 `0600` 创建。
- POSIX 后台进程建立独立进程组，停止时针对进程组；Windows 不组合 `shell: true` 与 `detached: true`，停止时尝试 `taskkill /T`。清理失败或未确认不得报告为成功。
- `shell-output` 以字节游标增量读取日志；只消费**已经完整解码且实际返回**的 UTF-8 内容，不吞掉多字节字符的残片，也不因显示上限跳过中间日志。没有完整新字符时可继续等待；等待必须可取消。
- 读取、状态查询失败如实报错，不能把日志丢失伪装成「没有新输出」。状态行保留任务编号与原始命令，方便识别。

## 为什么这样做

保留管道监听会让 Node 的事件循环继续持有句柄，`child.unref()` 本身无法保证宿主退出。Windows 的 `shell: true + detached: true` 又可能让输出丢失，所以两个平台不能照抄同一种进程配置。

日志游标是**字节数**，UTF-8 字符却可能跨多次写入；如果把读取量当成返回量推进，后续内容就永久看不到。输出状态和真实日志错误也必须区分，否则模型会基于错误事实继续工作。

## 代价与边界

日志需要磁盘空间，当前不自动轮转；用户需要清理长期残留的日志。跨平台进程树清理依赖操作系统工具与信号语义，无法把尝试终止等同于绝对保证没有后代存活。增量输出假定可读取的 UTF-8；任意损坏编码的无损恢复不作保证。

## 不变量

- 后台运行不能因父进程持有输出管道而阻止宿主退出。
- `shell-output` 不重复、不静默跳过已经成功返回以外的数据；截断与错误必须明示。
- 取消与停止必须如实报告清理结果，不能虚报成功。
- 对应行为由 `test/workspace.test.mjs` 持续保护。
