# TUI v0.3：对话贴顶、输入框和审批面板

v0.2 的对话贴底在短会话里把内容推到窗口底部，输入区只有一条分隔线，权限和统计在输入上方。v0.3 按 [终端布局与视觉验收规范](../design/tui-v0.3-layout-spec.md) 重排显示层；不改 Agent Loop、Permission 执行策略、Session 语义或工具协议。

本 ADR 取代 [ADR-0015](./0015-tui-v0.2-chat-interface.md) 中关于对话排列、输入区和状态行的具体描述；0015 保留为 v0.2 历史。

## 决定

- **对话从顶部开始**：日志视口第一行就是最早可见的用户消息；内容不足一屏时空白留在下方，不再用 top padding 贴底。新输出在用户未滚动时跟随最新，滚动时只增加偏移，不把视口拉回底部。
- **输入框固定在底部**：上边框、输入行、下边框三行；状态行（权限 + requests/tool calls/tokens）在框下方。最底下留 3 行缓冲，避免传统 conhost 的窗口底边吃掉状态行。
- **readline 的清除边界必须补画**：readline 从输入行清到屏幕底部，会擦掉输入框下边框和状态行；每次 prompt、按键和恢复输入后补画这两行与右侧竖线，再按 prompt 宽度和已输入内容把光标放回输入位置。输入行仍由 readline 管，不改写它的行编辑。
- **工具状态分层**：运行中 `●`，成功 `✓`，失败 `✗`，权限拒绝 `⊘`，未执行 `–`；失败/拒绝/未执行的原因放在下一行。工具事件用 `Read README.md`、`Shell: npm run check`，不重复打印同一条调用，`read` 不把文件内容刷进聊天区。
- **Shell 审批面板**：完整 workspace 和命令放在带边框的面板里，长命令按显示宽度换行、不截断危险尾部；`[Y] Allow once` / `[N] Deny` 明确列出，回答在下方输入框输入。面板超过视口时提示 PageUp/PageDown，完整命令保留在可滚动日志里。
- **外观降级**：Windows Terminal / VS Code / Linux 用 `❯ ✻ ● ✓ ✗ ⊘ – ┌┐└┘─│`；传统 conhost 退成 `> * o + x ! - +-|`。颜色仍是 16/256 色 + `NO_COLOR`，无颜色只靠符号和框线也能读。

## 为什么

v0.2 的贴底布局在长会话里没问题，但空会话或短回复会把内容压在窗口底部，和「对话从顶部往下读」的直觉相反；参考图和验收规范因此要求顶部排列。输入框加框、状态行下移，解决的是「输入不突出」和「不知道当前权限/花费」这两个直接可见的问题。

审批面板不是装饰：完整命令、真实 cwd、明确选项和可滚动查看必须同时存在，否则长命令或控制字符可能被摘要掩盖。面板只改变显示，`Permission` 的逐次询问、`isApproved` 的 y/yes 判定和默认拒绝逻辑都不动。

readline 清屏是 v0.3 最容易踩的坑：把状态行放在输入下方后，普通的 `rl.prompt()` 会直接把它擦掉。补画 chrome 而不是换掉 readline，是为了保留现有的行编辑、输入法、Ctrl-C/EOF 和审批并发行为。

## 代价与边界

- 输入框右侧竖线在读屏器/慢终端里可能有一帧被 readline 擦掉后补回；这是为了继续使用 readline 行编辑。
- 固定布局要求至少 12 行、30 列；日志只保留最近 2000 条逻辑行，不提供完整历史回滚。
- 宽度按近似显示宽度换行（CJK / emoji 按 2 列，组合字符按 0 列），不做完整 Unicode East Asian Width 表；长行硬换行，不做横向滚动。
- 审批面板超过视口时需要 PageUp/PageDown；不会把长命令悄悄截断成「看起来完整」。
- 没有鼠标、多行输入、工具详情展开、`/` 菜单或 Hooks；这些仍不在 v0.3 范围。
- 不是沙箱：审批「允许一次」只放行当前这条命令（[ADR-0013](./0013-permission-is-a-policy-not-a-sandbox.md)）。

## 不变量

- **输入永远在底部**：日志只改变输入框上方内容；输入框上下边框和状态行保持在固定行。
- **审批安全不因显示改变而削弱**：完整命令、实际 cwd、y/yes 判定、默认拒绝、取消链和审批通道关闭的区分保持原样。
- **Run log 不回灌模型**：它是 Session 的显示缓冲，不是 Transcript。
- **Thinking 只是等待状态**：第一段正文、工具调用或错误到达就消失，不能当成请求成功。
- **颜色/字形可缺失**：无颜色、无框线、窄终端、resize 都不能让 TUI 崩溃或吞掉审批。
- **退出交还 shell**：清掉定时器、键盘/resize 监听，关闭 readline，从最后一行下方换行；不切 alternate screen。
