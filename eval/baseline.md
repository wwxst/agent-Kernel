# 评测基线：结论、理由和适用边界

基线只证明**指定模型、指定代码、指定任务**当时的表现。跨模型、跨任务口径、跨 Git 提交的数字不能直接宣称是内核能力的提升。原始 JSON 保留在 `eval/baselines/`，本页只保留足以做决策的结论。

## 当前评测套件版本

当前代码中的评测套件标识为 `2026-11-21-eval-system-v1`，当前包含 22 个真实模型任务，并增加了请求级观测、缓存 Token、费用估算、A/B 对照、代码质量盲审和离线专项场景。

`2026-11-19-checkers-v2` 的三轮真实模型基线（固定提交 `76a024a`、hy3、20 个任务、并发 4，57/60）已推送到独立分支 [docs/eval-baseline-3rounds](https://github.com/wwxst/agent-Kernel/tree/docs/eval-baseline-3rounds/eval/baselines/2026-11-19-checkers-v2)，但尚未合并到当前 `main`，因此本分支不复制或覆盖那份原始归档。它是旧套件的历史对照，不能和当前 22 任务的新套件直接混算。

下面历史表格中的 v1 / v2 指的是当时的提示词与实验基线版本，不是新的检查器套件版本。**当前 `2026-11-21-eval-system-v1` 尚未建立新的真实模型基线**；需要配置模型 API 后重新运行评测，才能得到这套任务和当前内核的真实能力、稳定性与成本数据。

## 固定版本结论

| 版本 | 代码与模型 | 六轮通过 | 请求中位数 | 工具调用中位数 | Token 中位数 | 墙钟中位数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| v1（2026-11-04） | `e86cde4` / `3617371`，`hy3` | 119/120 | 101.5 | 99 | 139,040 | 79.0 秒 |
| v2（2026-11-05） | `eac798d`，`hy3` | 120/120 | 89.5 | 85.5 | 118,817 | 70.8 秒 |

两组均为 20 题、并发 4，同一天连续跑六轮。v2 代码标记为 `stability-2026-11-05-prompt-v2`。完整结果见 [v1 原始数据](./baselines/2026-11-04-hy3/) 与 [v2 原始数据](./baselines/2026-11-05-hy3-prompt-v2/)。

**采用 v2 的理由**：提示词要求模型每次只运行一条简单 Shell 命令，以减少复杂拼接、管道和 Shell 语法失败导致的额外往返。在该样本上，请求中位数下降 11.8%，Token 中位数下降 14.5%，墙钟中位数下降 10.4%；Token 六轮极差由 1.42 倍收窄到 1.22 倍。该实验支持这一提示词在这些任务上的取舍，**不能证明对所有 Shell 工作负载都有收益**。

仍然存在模型绕路：v2 中 `13-callback-to-promise` 的 Token 波动为 3.76 倍，`20-fix-email-regex` 为 2.51 倍，`08-extract-duplication` 为 1.40 倍。估算成本应使用中位数并留余量，不能按最好一轮。

## 不能过度解释分数

- 2026-11-14 审查发现的 **5 个历史检查器漏检点**已纳入 `2026-11-19-checkers-v2` 加强范围；另补充了嵌套目录扫描、常量提取、共享校验和 guard clause 的结构检查。具体改动见 [评测集说明](./README.md)。`eval:check` 仍只证明初始状态会失败，检查器严格性由 `test/eval-task-checkers.test.mjs` 的正反例测试保护。
- 所有结果都来自当时固定的 `hy3` 和评测任务；现行 `main` 已演进，不能继承旧版的 120/120 结论。
- `usage` 缺失不能填 0；请求次数、工具执行次数、Token 和墙钟是不同指标。诊断运行有 I/O 开销，不能和未开启追踪的时间直接比。
- 第一阶段单轮 DeepSeek-V4.1-Flash 的 20/20、178 请求、389,074 tokens、66.5 秒，仅作为历史样本，不用于和 `hy3` 比较内核强弱。
